# Database Migrations

## Overview

The LPR system now uses Alembic for database schema management, providing versioned migrations and rollback capabilities.

## Migration System Architecture

### Components
- **Alembic**: SQLAlchemy's migration framework
- **migrate.py**: Simplified migration command interface
- **migrations/**: Directory containing migration files
- **alembic.ini**: Alembic configuration

### Benefits
- **Version Control**: Track database schema changes over time
- **Rollback Support**: Safely revert schema changes if needed
- **Team Coordination**: Share schema changes across development team
- **Production Safety**: Test schema changes before deployment

## Common Operations

### Check Current Status
```bash
# Show current database revision
python3 migrate.py current

# Show migration history
python3 migrate.py history
```

### Create New Migration
```bash
# Auto-generate migration from model changes
python3 migrate.py create "Add user preferences table"

# This will:
# 1. Compare current database schema to models.py
# 2. Generate migration file with detected changes
# 3. Save to migrations/versions/
```

### Apply Migrations
```bash
# Upgrade to latest version
python3 migrate.py upgrade

# Upgrade to specific revision
python3 migrate.py upgrade abc123

# Downgrade to previous version
python3 migrate.py downgrade -1

# Downgrade to specific revision
python3 migrate.py downgrade xyz789
```

## Migration Workflow

### 1. Modify Models
Update your database models in `database/models.py`:

```python
# Add new column to existing table
class Camera(Base):
    __tablename__ = 'cameras'
    
    # ... existing columns ...
    
    # New column
    timezone = Column(String(50), default='UTC')
```

### 2. Generate Migration
```bash
python3 migrate.py create "Add timezone to cameras"
```

This creates a new file like:
```
migrations/versions/abc123_add_timezone_to_cameras.py
```

### 3. Review Migration
Always review the generated migration:

```python
def upgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.add_column('cameras', sa.Column('timezone', sa.String(length=50), nullable=True))
    # Set default value for existing records
    op.execute("UPDATE cameras SET timezone = 'UTC' WHERE timezone IS NULL")
    # ### end Alembic commands ###

def downgrade() -> None:
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_column('cameras', 'timezone')
    # ### end Alembic commands ###
```

### 4. Test Migration
```bash
# Apply migration
python3 migrate.py upgrade

# Test the change works
python3 start_lpr.py

# If issues, rollback
python3 migrate.py downgrade -1
```

### 5. Commit to Git
```bash
git add migrations/versions/abc123_add_timezone_to_cameras.py
git commit -m "Add timezone column to cameras table"
```

## Best Practices

### Migration Naming
Use descriptive messages:
```bash
# Good
python3 migrate.py create "Add timezone support to cameras"
python3 migrate.py create "Remove deprecated status column"
python3 migrate.py create "Create user_preferences table"

# Bad
python3 migrate.py create "Update db"
python3 migrate.py create "Changes"
```

### Data Migrations
For complex data transformations, add custom logic:

```python
def upgrade() -> None:
    # Schema changes
    op.add_column('detections', sa.Column('processed', sa.Boolean(), nullable=True))
    
    # Data migration
    connection = op.get_bind()
    connection.execute(
        "UPDATE detections SET processed = TRUE WHERE confidence > 0.8"
    )
    connection.execute(
        "UPDATE detections SET processed = FALSE WHERE confidence <= 0.8"
    )
    
    # Make column non-nullable after setting values
    op.alter_column('detections', 'processed', nullable=False)
```

### Testing Migrations
Always test both upgrade and downgrade:

```bash
# Test upgrade
python3 migrate.py upgrade

# Verify system works
python3 start_lpr.py

# Test downgrade
python3 migrate.py downgrade -1

# Verify system still works
python3 start_lpr.py

# Re-apply for production
python3 migrate.py upgrade
```

### SQLite Limitations
SQLite has limited ALTER TABLE support:
- Can't modify column types
- Can't drop columns directly
- Can't add NOT NULL columns without defaults

For complex changes, use table recreation:

```python
def upgrade() -> None:
    # Create new table with desired schema
    op.create_table('cameras_new',
        sa.Column('id', sa.String(36), nullable=False),
        sa.Column('name', sa.String(100), nullable=False),
        sa.Column('ip_address', sa.String(45), nullable=False),
        # ... other columns with modifications
        sa.PrimaryKeyConstraint('id')
    )
    
    # Copy data
    op.execute("""
        INSERT INTO cameras_new (id, name, ip_address, ...)
        SELECT id, name, ip_address, ... FROM cameras
    """)
    
    # Drop old table
    op.drop_table('cameras')
    
    # Rename new table
    op.rename_table('cameras_new', 'cameras')
```

## Troubleshooting

### Migration Fails
```bash
# Check current state
python3 migrate.py current

# Check what migration would do
./venv/bin/alembic upgrade --sql head

# Manual fix and stamp
./venv/bin/alembic stamp head
```

### Database Out of Sync
```bash
# Generate migration to sync
python3 migrate.py create "Sync database schema"

# Review and edit the generated file
# Apply the migration
python3 migrate.py upgrade
```

### Rollback Production Issue
```bash
# Identify target revision
python3 migrate.py history

# Rollback to known good state
python3 migrate.py downgrade <revision_id>

# Fix the issue and create new migration
python3 migrate.py create "Fix production issue"
python3 migrate.py upgrade
```

## Production Deployment

### Pre-deployment Checklist
1. ✅ All migrations tested locally
2. ✅ Database backup created
3. ✅ Migration rollback plan prepared
4. ✅ Service downtime planned (if needed)

### Deployment Steps
```bash
# 1. Backup database
cp data/license_plates.db data/backups/pre_deployment_$(date +%Y%m%d_%H%M%S).db

# 2. Apply migrations
python3 migrate.py upgrade

# 3. Verify migration success
python3 migrate.py current

# 4. Start services
python3 start_lpr.py

# 5. Verify system functionality
curl http://localhost:8001/health
```

### Emergency Rollback
```bash
# If deployment fails:
# 1. Stop services
python3 stop_all_services.py

# 2. Restore database backup
cp data/backups/pre_deployment_YYYYMMDD_HHMMSS.db data/license_plates.db

# 3. Rollback migrations
python3 migrate.py downgrade <previous_revision>

# 4. Restart services
python3 start_lpr.py
```
